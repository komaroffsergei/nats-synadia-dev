# Статус, источник и автоматический повтор сессии

Источник данных — Codex proxy. Изменения от 2026-09-08.

## Консоль владельца

- Заголовок по умолчанию — первое доступное пользовательское поручение (начало текста до 140 символов). Служебные оболочки остаются в ленте, но не становятся названием. Переименование хранится отдельно и имеет приоритет. Сброс возвращает первое поручение. Названия существующих публикаций не меняются.
- «Активна»: есть незавершённая физическая попытка. «Ожидание данных»: такая попытка есть, но события не поступали более 90 секунд. «Ответ завершён», «Ошибка», «Поток прерван» — последнее наблюдаемое завершение запроса. Явный `cancelled` отображается как «Остановлена». Это статусы запросов, а не утверждение о завершении задачи Codex.
- `source.status` содержит очищенные `userLabel` и `configId`. Конфигурация фиксируется в момент выбора upstream и при смене конфигурации для retry HTTP/WebSocket; её содержимое не передаётся. В карточке показывается конфигурация последнего подключения, а не предполагаемая конфигурация всех исторических запросов.
- Таблицы `source_users` и `session_sources` доступны только через owner API. Имена существующих пользователей можно восстановить из хранилища proxy по точному SHA256(username), не затрагивая сообщения или usage. Историческая конфигурация без события остаётся неизвестной.

## Эфир + автоповтор

Для действующей live-публикации `repeatWhenIdle: true` включает автоматический повтор. Переключатель доступен прямо в карточке выбранной сессии и в управлении эфиром. Для неопубликованной сессии кнопка открывает предварительный просмотр с этой настройкой; закрытая сессия не публикуется автоматически.

После завершения последней попытки и 15 секунд без событий сервер сохраняет доступную историю с выбранного начала. Сайт переходит в явно обозначенный «Повтор записи», проигрывает её с начала и зацикливает. Появление новых событий меняет режим обратно на live; сообщения обновляются без повторного учёта токенов. Пауза, выбранная самим зрителем, сохраняется. Незавершённый запрос без новых данных не считается остановленным и не запускает повтор.

Запись дополняется по SQLite cursor, поэтому поздно доставленные события не теряются на границе времени. Повторные snapshots контекста не заменяют оригинальный текст. Сохранённая запись переживает очистку 24-часовой истории и перезапуск; пределы — 8 MiB / 6000 кадров на публикацию и 128 MiB на весь архив. При превышении пределов консоль показывает проблему, live продолжает работать. Скрытие закрывает текущих зрителей и доступ к истории. В WebSocket передаётся короткое уведомление о новой записи; большой архив загружается через HTTP.
