# Эфир портфолио

Владелец управляет публикациями в `/console/` → **Эфир сайта**. Неопубликованные сессии не попадают ни в список, ни в публичный WebSocket. Источник событий остаётся прежним: Codex proxy → outbox → NATS → проектор. Эта функция ничего не отправляет модели и не запускает инструменты.

## Как опубликовать

1. В карточке нужной сессии нажать **Эфир на сайте** (либо открыть вкладку **Эфир сайта**). Выбранная сессия уже подставлена в форму. Задать понятное название для посетителей.
2. Выбрать **Прямой эфир** или **Запись с повтором**. Для записи по умолчанию подставляются последние пять минут сессии по датам её событий. Кнопка **Вся доступная история** подставляет полный доступный период. Поля показывают часовой пояс браузера; рядом указаны доступные события и текущее время сервера. Будущие даты, обратный порядок и период вне истории блокируют предпросмотр с пояснением.
3. Нажать **Предварительный просмотр**. Раскрыть служебный контекст и проверить текст. Для записи доступны и все промежуточные версии текста — они входят в воспроизведение.
4. Нажать **Опубликовать на сайте**. До этого шага ничего не становится публичным. Предварительный просмотр действует 15 минут и привязан к учётной записи владельца.
5. Управлять видимостью, порядком, скоростью, повтором и пропуском пауз в списке справа. У скрытой публикации появляется удаление.

Если выбранный фрагмент превышает 8 MiB или 6000 изменений текста, появляется **Подобрать фрагмент по лимиту**. Только по этой кнопке сервер убирает тихий хвост и последовательно сокращает период с начала, пока запись не помещается. Новые даты явно показываются в форме и сообщении над предпросмотром. Подбор не выходит за выбранные границы и ничего не публикует. Для записи оставшейся части можно выбрать другой период. Изменение модели, запросы к ней и расход токенов при подборе отсутствуют.

Прямой эфир включает историю с указанного начала и последующие события выбранной сессии. При отсутствии событий сайт показывает «Нет новых событий», а не завершение задачи. Обычная текстовая история хранится 24 часа; старый текст живой публикации со временем исчезает.

Запись фиксирует события выбранного периода при предварительном просмотре. После публикации она хранится отдельно от суточной истории. Повтор — исключительно проигрывание текста в браузере; токены повторно не начисляются. Время в строках остаётся исходным. Режим явно подписан «Повтор записи».

Публикация действует до скрытия/удаления. Это отдельный механизм от временных ссылок `/live/<token>`. Кнопка **Временная ссылка** открывает предпросмотр такой ссылки; отметка **Есть временная ссылка** означает только наличие действующей ссылки. Она не означает публикацию в эфире портфолио. Из окна готовой ссылки можно перейти к настройке эфира; сам переход ничего не публикует. Скрытие удаляет публикацию из списка, закрывает её активные WebSocket-подключения и запрещает загрузку истории (HTTP 410). Уже прочитанный посетителем или самостоятельно сохранённый текст отозвать невозможно.

## Контракты

| Доступ | Маршрут | Назначение |
| --- | --- | --- |
| public GET | `/api/public/broadcasts` | Только видимые публикации, без исходных ID сессий |
| public GET | `/api/public/broadcasts/:id?before=...` | Живой снимок с пагинацией либо зафиксированные кадры записи |
| public WS | `/public/ws?broadcast=:id` | `ready`, `broadcast`, `broadcast_changed`, `revoked`; восстановление полным снимком |
| owner GET | `/api/v1/monitor/broadcasts` | Все публикации и настройки |
| owner POST | `/api/v1/monitor/broadcasts/preview` | Приватная подготовка фрагмента |
| owner GET | `/api/v1/monitor/broadcasts/range?sessionId=...` | Только даты и число сохранённых снимков выбранной сессии, текущее время сервера |
| owner POST | `/api/v1/monitor/broadcasts` | Публикация проверенного `draftId` |
| owner PATCH / DELETE | `/api/v1/monitor/broadcasts/:id` | Настройки, скрытие, удаление |

Закрытые маршруты используют существующий Nginx Basic Auth и внутренние `X-Monitor-Key` / `X-Monitor-Owner`. Изменяющие запросы требуют правильного Origin и JSON Content-Type. Главный сайт проксирует только публичные маршруты; браузер отправляет публичные fetch без credentials. WS допускает origins из `MONITOR_ORIGIN` и `MONITOR_PUBLIC_ORIGINS` (по умолчанию `https://komaroff-dev.ru`).

Исходные идентификаторы инструментов и групп заменяются идентификаторами конкретной публикации. Текст поступает уже очищенным существующим proxy observer; дополнительные поля трафика не публикуются. Предварительный просмотр нужен и для проверки самим владельцем содержимого сессии. HTML/Markdown из событий не выполняется: Vue/Angular выводят текст, а не `innerHTML`.

## Хранение и ограничения

- Отдельные таблицы SQLite `broadcasts` и `broadcast_drafts`, без изменения схемы событий и токенов.
- Запись: до 8 MiB, до 6000 сохранённых изменений. Архив: до 128 MiB и 50 публикаций, включая скрытые. Удаление освобождает логический объём; SQLite может повторно использовать освободившиеся страницы.
- Предварительные просмотры: не больше 12 одновременно; истекают через 15 минут.
- Метаданные записей хранятся отдельно от кадров: обновление списка не десериализует весь архив.
- Доставка объединяет обновления в окно 80 мс и переиспользует живой снимок для зрителей одной публикации. Максимум 100 WS-подключений; переполнение 2 MiB закрывает медленного зрителя с требованием переподключиться.
- Сайт обновляет список раз в 5 секунд. Удаление/скрытие уже открытой публикации доставляется через WS сразу после изменения; REST-проверка страхует потерю соединения.

## Проверка и выпуск

```sh
cd examples/agent-web-ui
bun test server/monitor/
bunx vue-tsc --noEmit
```

Образ собирается вне VPS через `docker/Dockerfile`. Выпуск меняет только API/UI Codex Monitor и проектор; proxy и publisher не требуют пересоздания. Сохранить предыдущие compose, env, Nginx и образ. Схема добавочная: предыдущая версия игнорирует новые таблицы. Для отката вернуть старые образы и конфигурацию. Архив публикаций не удалять. Для отключения публичного эфира закрыть новые публичные маршруты на основном сайте или скрыть все публикации в панели.

Синтетические тестовые публикации допустимы только на локальном стенде. В production владелец выбирает сессии самостоятельно.
